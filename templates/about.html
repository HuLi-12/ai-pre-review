关于 AI Review Cockpit

它不是把整个 diff 直接丢给大模型，而是围绕 Changed Lines、Evidence Chain 和 Confidence Gate 组织一次可解释、低噪声的 PR Review。

为什么不是普通 AI Review
减少无关上下文
普通 diff-to-LLM 容易把旧代码问题当成新问题；Cockpit 只把本次变更行作为主要审查对象。
控制误报
低置信结果默认不进入高优先级展示，高置信或高风险结果才进入 GitHub Ready。
保留证据
每条 finding 尽量绑定规则、代码片段、置信度原因和建议，方便 reviewer 快速判断。

系统架构和未来扩展方向
当前架构
  • FastAPI 负责任务创建、状态查询、报告接口和页面渲染。
  • ReviewEngine 负责 GitHub PR 获取、静态规则、AI Review、去重和报告生成。
  • Jinja2 + Bootstrap 负责工具入口、任务进度、报告和评测展示。
未来扩展方向
  • 接入更多模型并按任务类型自动路由。
  • 把 reviewer 反馈沉淀为规则和置信度校准数据。
  • 支持行级 GitHub review comment 和团队级规则配置。
